## 规则系统怎么挂（已评估，未实现）

三层，不要把 D&D 写进通用卡面：

1. **通用 OC 层**（现有，所有世界都有）：身份、故事、模块、时间线、关系、图库。
2. **世界类型**（下一步）：只是标签 + 以后用来决定「要不要显示规则页」。
3. **规则游玩层**（更后面）：`character.play = { system, version, data }`，`data` 对核心代码是不透明 JSON。D&D 的力量/HP/法术只活在 `src/systems/dnd5e/`，通过角色页多一个「规则卡」标签进来。不要做成第四种模块。

原则：

- 不要按系统 fork `CharacterSheet.tsx`。
- 不要用滑块/雷达表达 STR、HP、法术位。
- 建卡向导（若做）是独立流程，做完落到通用卡 + 可选规则卡；成卡页继续默认唯读。
- 核心 `normalizeCharacter` 不解析 `play.data`；坏数据只让规则标签空着，不能拖垮通用卡。

分阶段（都还没做）：

1. 世界类型下拉（上面第 1 条）。
2. 系统注册表 + 不透明 `play` 字段 + 空的规则卡标签（仅非 generic 世界显示）。
3. D&D 规则卡按下方定稿实现（自动加值、判定页、可选法术模块、独立骰子按钮）。
4. 短开卡向导。
5. 其他系统各放自己的 `src/systems/<id>/`。

## D&D 规则卡定稿（已确认，未实现）

参考玩家 Google 表结构。规则按 **5e 最新版（2024）**；文案跟 App **简中**。通用卡仍管外观和故事。

### 判定页（点任何加值打开）

- 预填名称和基础加值（可展开：属性调整值 + 熟练 + 其他）。
- 优势 / 正常 / 劣势。
- 平面额外加值（可正可负）。
- 额外骰：可增删多行，每行 `[数量] D [面数]`（dropdown：d4/d6/d8/d10/d12/d20/d100）。
- 目标 DC 可空（空则只出总数，不判通过）。攻击命中时标签为 AC。
- **马上判定**：系统掷 d20（优势两次取高，劣势取低）以及所有额外骰。
- **填入手骰**：只填一颗已经取过的 d20；额外骰默认仍由系统掷，单颗可改手填。
- 输出：各骰面、加值、总计；有 DC/AC 则通过/未过。d20 为 1 或 20 时额外标注 **大失败 / 大成功**（技能检定同样标注，但不改通过算法）。
- 不提供对抗检定。
- 死亡豁免：默认 DC 10；自然 1 = 两次失败，自然 20 = 清醒且 1 HP（2024）。

攻击行两个独立按钮：**命中**（d20 判定页）和 **伤害**（伤害骰 + 调整值，不是 d20；2024 重击只加倍武器骰）。

### 规则卡模块

1. 摘要：职业、等级、熟练加值、经验。
2. 属性：点调整值 → 属性检定。体质用「体质」不是「体魄」。
3. 豁免：点加值 → 豁免。
4. 技能 18 项：加值 | 名称 | 熟练 | 优劣预设。点加值打开判定。
5. 生存：HP / 临时 HP / AC 构成 / 速度 / 生命骰 / 先攻（**d20+敏捷**，点加值）/ 死亡豁免 / 激励资源。
6. 攻击：命中按公式自动算（熟练 + 对应属性 + 杂项）；表上刺剑 +0 视为原卡 bug，不沿用。
7. 语言与熟练：按来源分组，不判定。
8. 特征：可显示次数；吟游激励等可作为判定页额外骰来源。
9. **法术（可开关）**：默认施法职业开、非施法关，角色可手关。内含法术位、DC、法术攻击加值（可点判定）、法术表（职业可选列表）、法术书（已知/准备/已抄录）。
10. **独立骰子按钮**：随时打开自由骰盘（多行 nDx，无 DC、无优劣），替代对抗检定。

加值公式由规则卡计算，不手填最终命中值。不内置全套资料书；法术表可用精简 SRD/免费表，缺的允许手填。
