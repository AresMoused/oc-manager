## 规则系统怎么挂（已评估，未实现）

三层，不要把 D&D 写进通用卡面：

1. **通用 OC 层**（现有，所有世界都有）：身份、故事、模块、时间线、关系、图库。
2. **世界类型**（下一步）：只是标签 + 以后用来决定「要不要显示规则页」。
3. **规则游玩层**（更后面）：`character.play = { system, version, data }`，`data` 对核心代码是不透明 JSON。D&D 的力量/HP/法术只活在 `src/systems/dnd5e/`，通过角色页多一个「规则卡」标签进来。不要做成第四种模块。

原则：

- 不要按系统 fork `CharacterSheet.tsx`。
- 不要用滑块/雷达表达 STR、HP、法术位。
- 建卡向导（若做）是独立流程，做完落到通用卡 + 可选规则卡；成卡页继续默认唯读。
- 核心 `normalizeCharacter` 不解析 `play.data`；坏数据只让规则标签空着，不能拖垮通用卡。

分阶段（都还没做）：

1. 世界类型下拉（上面第 1 条）。
2. 系统注册表 + 不透明 `play` 字段 + 空的规则卡标签（仅非 generic 世界显示）。
3. D&D 1 级可填规则卡（属性、HP、AC、技能），少量派生值，不内置全书资料。
4. 短开卡向导。
5. 其他系统各放自己的 `src/systems/<id>/`。
